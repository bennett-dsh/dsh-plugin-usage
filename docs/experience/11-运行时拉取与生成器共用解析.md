# 11 · 运行时拉取与生成器必须共用一份解析

## 症状

需求是「让所有用户自己点按钮拉最新价目」。最省事的写法是把 `scripts/gen-prices.mjs`
里的 `parseZen` / `parseDeepSeek` 复制到宿主半，改成一个 RPC。**没有犯这个错**，但
差一点：生成器与运行时读的是同一批页面，任何一边改动都会让「我拉到的表」和「发版带的
表」对同一个页面给出两种答案 —— 而这种分歧不会报错，只会让同一次调用在两个人那里算
出不同的钱。

## 根因（要防的那件事）

页面解析是**对上游布局的猜测**：表靠表头文字定位、价格靠 `"$1.36 $0.68"` 拆 list/value、
`(> 200K tokens)` 行进 surcharge。这类规则一旦有第二份拷贝，就会出现「生成器修了、
运行时没修」的状态：CI 的 PR 是绿的，用户点按钮拉到的是旧的读法。

## 做法

- 解析与合并只有一份：`src/host/reference-parse.js`（`parseTables` / `money` /
  `splitQualifier` / `parseZen` / `parseDeepSeek` / `buildReferenceTable` /
  `validateReferenceTable`）。生成器 `scripts/gen-prices.mjs` 与运行时
  `src/host/reference-refresh.js` 都 `import` 它。
- 校验也只有一份：生成器落盘前、运行时换表前、**以及从磁盘读回上一次拉到的表时**，
  跑的是同一个 `validateReferenceTable`。三道关，一个判据。
- 换表只有一个插槽：`pricing.js` 的 `active`（`setReferenceTable` / `referenceOrigin`），
  阶梯的每一级都通过 `referenceTable()` 读表，所以不会出现「字面命中用新表、别名命中用旧表」。

## 证据

- `tests/reference-refresh.test.js` 的 fixture 是**真实响应**（`tests/fixtures/pricing/zen.html`
  与 `deepseek.html`，2026-11-19 抓取），页面改版会在测试里红，而不是在用户的账单上红。
- 同一文件覆盖了失败语义：HTTP 503 → `code: http`；`TimeoutError` → `code: timeout`；
  只剩运维页 → `code: parse`；能解析但只有 3 行 → `code: table-invalid`。四种原因，
  界面给四句话——「连不上」和「页面改版了」对用户是两种不同的决定。
- 端到端冒烟（`DSH_HOME` 指向临时目录）：`usage/refresh` 873 ms 返回 92 个模型、
  落盘成功、`referenceOrigin()` 由 `builtin` 变 `fetched`，`{reset:true}` 之后回到 `builtin`。

## 顺带的一条：长任务端点不要走 Remote 优先的 `hostCall`

`hostCall` 先试原生 Remote、失败再退 Fetch。`refresh` 在宿主里做联网 I/O，是 **async
handler**；Fetch 路由由 `rpc.js` 的 `dispatch` `await fn(args)`（可证），而 Remote 那条
链路的 await 语义属于网关实现，本插件无法取证。所以客户端为它单开 `hostCallLong`：
直接走 HTTP 路由（404/405 再退旧 RPC 通道），只读端点继续用 Remote 优先。

## 追加（同日）：节假日历必须同一次拉取，于是先把派生值请出缓存

需求追加为「节假日与价目表同时获取，不为节假日开新 UI」。这暴露了上一段的同一个病根：
峰谷分桶存在**折叠记录**里，而 `fold-cache` 的签名把日历的 `capturedAt` 绑了进去 ——
所以「换历」在今天等于「全部会话日志重扫一次」（这机器上 258 会话时 12.5 s，441 会话更久）。

实测推翻了那个成本假设：13,826 条记录 **100%** 同时带 `time` 与分桶，全套缓存 JSON 解析
131 ms、按 `time` 重新分类 16.7 ms、重建聚合索引 11.7 ms。也就是说分桶是纯派生值，存下来
才是问题本身。

- `fold.js` 不再写 `tokens`，缓存只存原料（时间戳 + 四个计数）；分桶在 `aggregate` /
  `costOf` 里按当时生效的历现算。
- `foldSignature()` = 版本号，不再含日历；**v1 条目仍可读**（`legacyFoldSignature` 命中
  后把分桶删掉），所以升级不用重扫 —— 把「一次性代价」也省掉了。
- 换历后必须 `rebuildIndex`：聚合单元里存的是按旧历算好的峰谷和。`query.test.js` 钉了
  「旧单元在重建前仍是旧价、重建后同一批记录换价」。
- 价目与日历同一次点击、同一次原子写落盘（`reference-store` v2），界面上只多一句
  「节假日历没拉到」的提示，没有新按钮。
