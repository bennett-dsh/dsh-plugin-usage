# 08 · 槽位 id 对齐

## 症状

设置页导航行显示的是官方齿轮，不是插件图标；控制台**没有任何报错**，插件其余功能正常。

## 根因

0.2.2-rc.1 的 `settings.section.icon` 不是普通 list slot：nav rows 用
`renderSlot("settings.section.icon", { size, active }, { only: row.id })` 渲染，按**注册 id**
匹配目标 section。注册 id 与 section id（`token-stats`）对不上时，条目永不渲染、也不报错。
更早的内核（0.2.1 及以前）根本没有这个槽，`slots.inject` 不触发，同样回落到齿轮。

## 证据

- `tests/client-settings-icon.test.js` 四条：注册 id 必须等于 section id、旧 DOM 补缺必须删净、
  图标按 `size` 渲染且只用 `currentColor`、`dsh.client.inject` 必须声明
  `@deepseek-ai/dsh-client-ui-settings-general`；
- `CHANGELOG.md` 0.5.1：删掉 0.2.1 时代的「属性标记 + CSS mask + MutationObserver」补缺；
- `src/client/index.js` 的注释保留了官方契约与「对不上的 id 永不渲染」这条。

## 结论

- 注册 id 必须与 section id 严格一致（两处都写 `token-stats`），并由门钉住；
- 官方补上能力后，旧补缺要**整体删除**，不能留成第二条并行路径（会画两个字形）；
- 旧内核没有该槽时静默退化成官方齿轮，不能因此抛错或拖垮设置页。
