# 06 · 读请求触发写

## 症状

代码里有完整的加载态（骨架屏、进度条、「正在统计 n/N 个会话…」），但屏幕上**一帧都看不到**；
连着重启十几次，面板打开时数据已经算完（或已经显示半份结果）。

## 根因

全量统计在 `apply` 里预热。面板是按需挂载的，进程启动到用户点开 设置 → 用量统计 之间早就过去了：
暖缓存约 0.78 s、冷缓存约 12 s 的「缓存加载」全部发生在用户看见面板之前。

## 证据

- `src/host/scan.js` 的 `startBackfillOnDemand` 注释：「the user restarted a dozen times and saw
  nothing」；
- `CHANGELOG.md` 0.4.6 记录了改造与暖/冷缓存数字；0.4.5 记录「整段 computing 都是加载态」；
- `tests/lazy-backfill.test.js` 的接线门断言 `query` 处理器必须调用 `startBackfillOnDemand`，
  且 `apply` 不得再直接 `runBackfill`（防止有人「顺手」改回启动时预热）。

## 结论

- 统计由第一次查询拉起：**面板打开的那一刻就是统计开始的那一刻**，加载态可见时长 = 工作本身时长；
- 查询是幂等的：`state.backfill.started` 闩住，只有第一次真正启动（不能用 `status` 当守卫，
  调用方会先把它置成 `running` 好让这一帧就带上加载态）；
- 写入的只是派生物缓存（可整目录删除），不碰用户数据、不写设置；
- 后台任务带 rejection 兜底，`ctx.get` 抛错也不能让一个读请求弄死进程。
