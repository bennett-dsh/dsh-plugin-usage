# 09 · 测试污染真实缓存

## 症状

整套测试**第一次**跑全绿；同一台机器**第二次**跑，`tests/scan.test.js` 的
「a persisted log that really shrank is folded again from the start」失败：
`readFrom` 是 `null`（期望 `0`），日志根本没有被读取。第三次、第四次同样失败。

## 根因

`scanPersisted()` 的 `beginPass()` 在 `options` 未指定 `cache:false` 时使用**真实的**
`cacheDir()`（`<DSH_HOME>/cache/dsh-plugin-usage/fold`）。`tests/scan.test.js` 里两个用于
验证 watermark / shrink 的用例没有传 `cache:false`，于是：

1. 第一次运行：用例折叠虚构会话 `s1`，`finishPass()` 把 `s1.json`（`revision: 'r2'`）写进真实缓存；
2. 第二次运行：同一用例的 `processHeader()` 先 `readEntry('s1')`，命中上次写的条目
   （`revision` 相同），`hydrateFromCache()` 直接返回，**不会**走到 `open().read()`；
3. 断言里的 `readFrom` 永远是 `null`。

这是测试**自己把自己毒死**：不是产品回归，也不是偶发；第一次运行的成功正是第二次失败的原因。

## 证据

- 真实缓存里出现了非会话文件：`<DSH_HOME>/cache/dsh-plugin-usage/fold/s1.json`（80 B，
  时间戳与 `npm test` 重合）；正常会话文件名是 `session-*.json`。
- 修法：两个用例都传 `{ cache: false }`（它们测试的是水位/缩短修复，不是缓存）；
  修复后单文件与整套测试均可重复运行。
- 门：`tests/scan.test.js` 的注释写明了「不要在这里启用缓存」；`tests/fold-cache.test.js`
  始终使用 `mkdtemp` 临时目录。

## 结论

- 不测缓存的扫描用例一律 `cache: false` 或显式 `cacheDir` 到临时目录；
- **测试不得写真实缓存目录**：它会跨运行持久化，且只影响「第二次跑」，最容易在发版前骗过自己；
- 看到「第一次全绿、第二次红」先怀疑测试写了共享位置，而不是代码随机失败。
